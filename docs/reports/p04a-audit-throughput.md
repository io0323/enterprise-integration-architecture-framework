# P04a ④ 監査記録の追記の性能(ローカルでの目安)

- 日付: 2026-09-28〜29
- 対象: `platform/audit` の `AuditLog.append`(ADR-0017 §4)、Issue #6
- **ローカルの開発機での目安であり、本番の性能値ではない。** 本番の値は、本番と同じ DB の構成(ストレージ・`synchronous_commit`・接続数)で計り直す。

## 1. 計測環境

| 項目 | 値 |
|---|---|
| マシン | Apple M3(macOS) |
| Docker | Docker Engine 29.8.0(linux/arm64)。Docker に割り当てた CPU は 8、メモリは 7.75 GiB(`docker info` の NCPU = 8、MemTotal = 8,319,770,624 bytes) |
| PostgreSQL | `images.env` の `POSTGRES_IMAGE`(postgres 18.6-alpine)を Testcontainers で起動。設定は既定のまま(`synchronous_commit=on`) |
| クライアント | JDK 21(aarch64)、PostgreSQL JDBC 42.7.13、HikariCP 7.1.0(同時実行数と同じ数の接続) |
| 同時に動いていたもの | 別のプロジェクトのコンテナ 7 つ(2 回目以降の計測)。ばらつきの一因になりうる |

## 2. 計測の方法

`AuditThroughputIT`(`./gradlew :platform:audit:integrationTest --tests '*AuditThroughputIT'`)。結果は `platform/audit/build/reports/audit/throughput.md` に出る。

- **chained**: `AuditLog.append` を 1 トランザクションで 1 件実行する。トランザクションの中で `SELECT current_setting('transaction_isolation')`・`pg_advisory_xact_lock`・末尾の `SELECT`・`INSERT` を行い、コミットでロックが外れる。
- **plain**(比較の基準): 同じ列の別のテーブルに、ロックもハッシュもなしで `INSERT` する(`seq` はシーケンス)。
- 同時実行数ごとに新しい DB を作り、200 件で慣らしてから 2,000 件を計る。
- 3・4 回目の計測では、同時実行数ごとに 3 回計って中央値(最小〜最大)を出した。あわせて、別の接続から `pg_stat_activity` を 2 ms ごとに見て、advisory lock を待っている接続の数の平均を記録した。
- 1 件の平均の所要時間は「同時実行数 ÷ 件数/秒」で求めた。
- どの計測でも、終わった後にチェーンを検証し、欠番・分岐がないことを確かめている。

## 4. 考察

- **目安**: 1 つのサービスの DB で、chained は **毎秒 1,000〜2,000 件程度**。同時実行数を増やしても、毎秒 2,000 件前後で頭打ちになる。plain は同時実行数に応じて伸びる(毎秒 3,000〜14,000 件)。
- **頭打ちの理由は、追記を直列にしたこと**: ロックを待っている接続の数の平均は、同時実行数 4 で 2.4、8 で 6.4、16 で 14.3 だった。ほかの接続はほぼ常にロックを待っている。1 件の平均の所要時間は、同時実行数にほぼ比例して延びる(0.8 ms → 7.7 ms)。ロックを持つ区間(末尾の読み込み・INSERT・コミット)が 1 件あたり 0.5 ms 前後で、これが上限を決めている。
- **1 回目の同時実行数 4(695 件/秒)は、外れ値と判断した**:
  - 同じ条件の 3・4 回目では、6 回の計測が 1,288〜2,175 件/秒だった。1 回目のほかの値(同時実行数 1・16)は、3・4 回目と同じ範囲だった。
  - ロックの待ちは同時実行数に応じて増えるだけで、同時実行数 4 だけが遅くなる傾向は見られなかった。
  - 1 回の実行の中でも ±30% 程度のばらつきがある。1 回目は計測の方法を改める前で、同時実行数ごとに 1 回しか計っていない。
- **業務の処理への影響**: ロックは業務のトランザクションのコミットまで持たれる(同じトランザクションで追記するため)。業務のトランザクションが長いと、その分だけほかの追記が待たされる。監査を記録するトランザクションは短く保つ(外部の呼び出しをトランザクションの中で行わない)。
